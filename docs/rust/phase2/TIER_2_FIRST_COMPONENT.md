## Technical Details

### FFI Architecture

```
C++ Entry Point (ble_scan_parser.cc)
    ↓
C++ Wrapper (wrapper_functions.cc)
    ↓
CXX Bridge (cxx.rs)
    ↓
Rust Implementation (lib.rs)
```

**Key FFI Types**:
- `ScanRecord` - Opaque C++ type for parsed data
- `UuidFormat` - Shared enum between Rust and C++
- `UuidListBuilderForTest` - C++ helper for testing

### Build.rs Design

The `build.rs` script implements the hybrid build pattern:

1. **Find Workspace Root**: Uses `.gn` marker file
2. **Check for GN Output**: Looks for `out/Default/` directory
3. **Provide Helpful Warnings**: Clear messages if GN not run
4. **Configure CXX Build**: 
   - Includes Chromium root directory
   - Adds GN-generated header paths if available
   - Compiles C++ wrapper functions
   - Links C++ standard library

### Dependencies

**Rust Dependencies**:
- `cxx = "1.0"` - Type-safe C++ FFI
- `cxx-build = "1.0"` - Build-time CXX bridge compilation

**C++ Dependencies** (from GN):
- `//base` - Chromium base library
- `//device/bluetooth/public/cpp` - Bluetooth types
- `//build/rust:cxx_cppdeps` - CXX runtime support

## Lessons Learned

### What Worked Well

1. **Existing Infrastructure**
   - Component already had Cargo setup
   - CXX bridge already defined
   - build.rs already implemented hybrid approach

2. **Documentation-First Approach**
   - Creating README before testing helped clarify requirements
   - Documentation serves as specification

3. **Helper Scripts**
   - build_hybrid.sh makes complex builds approachable
   - Script can be template for future Tier 2 components

4. **Workspace Integration**
   - Adding to workspace was straightforward
   - No conflicts with existing components

### Challenges Encountered

1. **GN Dependency**
   - Cannot build without GN infrastructure
   - Adds complexity for developers
   - Not all developers have GN setup

2. **Platform Limitations**
   - Component is ChromeOS-only
   - Cannot test on all platforms
   - May complicate CI/CD

3. **Documentation Needed**
   - Hybrid build pattern not intuitive
   - Requires more documentation than Tier 1
   - Need to explain why hybrid is necessary

### Recommendations for Next Tier 2 Component

1. **Pre-Migration Checklist**
   - Verify component has Cargo.toml
   - Check build.rs handles GN dependencies
   - Ensure FFI bridge is well-defined
   - Test on target platforms

2. **Documentation Template**
   - Use BLE parser README as template
   - Customize for component specifics
   - Include build requirements prominently

3. **Build Script Template**
   - Use build_hybrid.sh as template
   - Adjust Ninja target paths
   - Keep helpful error messages

4. **Testing Strategy**
   - Plan for both Cargo and GN tests
   - Verify FFI integration thoroughly
   - Test on all supported platforms
